## 行为

- 仅硬件门控后的 B 启用现有保留解码器策略，与 C 的开关和小队列解耦。B 已成功提交显示后，250ms积压或容量溢出属于参考链丢失，可保留解码器、请求IDR，不调用flush。首次输出前、格式/Surface变化和明确异常仍保留硬恢复。
- 重复参考链丢失合并为正在进行的恢复；关键帧请求沿用每秒最多一次的入口限频。重复丢失使旧IDR失效，但不延长已经开始的新IDR输出截止时间。
- 新IDR成功送入解码器后，1秒没有可提交的有效输出，禁用该流的软恢复并升级硬恢复。这个超时来自既有C策略，不是实测最优阈值。旧输出由PTS边界过滤，避免恢复后重新显示历史帧。
- B 新增输出停滞检测：自上次有效输出或状态重置后，至少30个输入已被 MediaCodec 接受，且从第一个未完成输入起至少1.5秒没有有效输出，才触发一次恢复。已有恢复期间不叠加触发，正常输出或解码器更换清除该证据。它不等于30次网络收到帧，不会因空闲静止画面自行计数。
- 收到依赖帧而仍等待关键帧时，每5秒最多记录一次 `recovery wait=keyframe-input`，继续既有限频请求；不能把未收到IDR当作硬解故障。这条路径不承诺仅靠重建车机解码器就能迫使手机发送IDR。
- 不改变分辨率、帧率、音乐缓冲、线程优先级、网络参数、USB请求或250ms阈值。B-output1的输出批次仍最多8个、零超时读取，不等待凑批。没有加入独立输出线程。

## 验证与限制
