# ADR-0008：原厂导航音频接入

- 状态：Accepted
- 日期：2026-11-02
- 作者：Codex
- 最后修改：2026-11-02

## 上下文

原厂高德反编译链路按 TTS 播放申请及归还焦点；本机 H53 框架导航播报流为 11。DiPlay 接收 CarPlay PCM，流会话寿命不等于一句播报寿命。原有焦点随 renderer 存活，可能长时间占用导航焦点。原厂分析见工作区 output/factory-amap-reverse-20261102/reports/audio-static.md。

## 决策

沿用 AudioManager 与已反射验证的 OEM stream 常量；在吉利导航流首段非空 PCM 时申请一次焦点，实际 AudioTrack 队列排空且输入静默 500ms 后释放。拒绝或失去焦点时该段静音消费，不在段内抢回焦点。500ms 是 CarPlay 缺少原厂 TTS 队列完成事件时的本项目启发式，不是原厂常量。

精确 API18/C3ALFUS/H53.00060 平台禁用未证实的 stream25 导航提示音映射，回到语音流11；原车导航音量直接读写该流实际音量级数。仅已核实专用变体默认启用原车声音配置，保存过的用户选择优先。HUD 沿用 oem-sequence 候选中的 10019/10001 原厂接收器协议，保持手动试验开关。

## 后果

正面：焦点寿命接近播报实际播放，音量归原车导航通道管理。
负面：500ms 静默窗口可能拆分有较长停顿的播报，或将连续播报合并。CarPlay PCM 与原厂 TTS 不是同一输入；真实压低/恢复与系统事件需实车验证。

## 替代方案

- 按 renderer 生命周期持有：持续流可能长期占用，未选。
- 固定短定时器释放：忽略硬件未播完的缓冲，未选。
- 直接接入原厂 Policy SDK：存在签名限制且没有必要替换已核实 stream 通道，未选。

## 撤销条件

实车出现播报截断、音乐恢复异常或焦点冲突时停用原车声音配置并回退基线；若取得可靠的上游播报完成事件，替换静默推断并重新验收。
