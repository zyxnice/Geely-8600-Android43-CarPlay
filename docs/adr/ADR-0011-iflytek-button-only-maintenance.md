# ADR-0011：固定H53讯飞唤醒限制作为独立维护候选

- 状态：Accepted（维护方案已采用，不表示实车验收通过）
- 日期：2026-11-04
- 作者：Codex，依据用户只保留按键唤醒的要求
- 最后修改：2026-11-04

## 上下文

原厂讯飞设置关闭后仍存在后台音频采集及唤醒恢复。用户仅需实体按键后的识别。现有独立导航兼容APK仅处理缺失服务绑定，无法控制讯飞内部唤醒生命周期；DiPlay亦不应拥有原厂语音开关或系统文件维护职责。

## 决策

仅对C3ALFUS/API18/06.03.08600.H53.00060和固定hash原ODEX使用定长补丁，限制7个ma唤醒入口，保持原APK签名、ODEX布局、主动识别及停止通路。离线构建、隔离Dalvik探针和维护脚本独立保存在scripts/iflytek-button-only，不参与DiPlay构建或自启动。安装和恢复保存被映射文件的硬链接并检查/system只读；不自动部署、不禁用整个应用、不调整麦克风权限。

保留原厂关闭的连续对话等设置。用户报告纯唤醒词仍响应，尚需无自动调用干扰的现场复测；状态必须维持“验收未通过”。

## 后果

正面：作用域固定、原APK签名保留、候选可重现及核验、原件可恢复；DiPlay与导航兼容APK职责不扩大。

负面：深度绑定特定固件，无法推广到其他版本；免唤醒确认/选择也被关闭；内存未明显减少；需要系统级维护与独立车测，原厂其它启动请求仍可能进入主动识别。CPU改善不能替代功能验收。

## 替代方案

- 仅关闭原厂设置：已观察到仍录音，不满足目标。
- 禁用整包或撤销录音权限：会破坏按键识别，未采用。
- 重签重组APK：增加签名、权限与依赖风险，未采用。
- 在DiPlay或导航兼容APK中反复杀讯飞：职责越界且引入重拉起与音频风险，未采用。
- 支持按键后的口头确认：需要更细的会话生命周期控制，本轮用户明确不要其它免唤醒功能，未扩展。

## 撤销条件

若按键识别、电话/CarPlay音频恢复受损，候选不能稳定加载，或无法控制空闲录音，应恢复固定原件并核验进程及音频状态。固件或原件hash变化即停止适用。若后续以原厂受支持开关可靠满足目标，应替代该补丁。
