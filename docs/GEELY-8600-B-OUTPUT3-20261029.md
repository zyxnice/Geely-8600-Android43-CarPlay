# B-output3：连续性与跟手联合候选

## 范围与证据

用户实车反馈：output1 更跟手但画面断续，output2 画面更连贯但操作响应较慢，两版音乐正常。目标是兼顾两项体验；当前尚未达到用户验收要求。

Decision: code-change。已确认队列超过 250 ms 时会连同已有关键帧一起清空，输入等待每次最多阻塞 10 ms；这些是可改善的机制，不足以证明全部卡顿根因。队列积压的上游原因仍待定位。

## 本次改动边界

- B/H264 积压时，在下一个配置、Surface 或 Resync 控制之前，取最新且未超过 250 ms 的 IDR，保留其后依赖帧。没有合格 IDR 时保持原有恢复流程。
- 保留 output2 的恢复策略与输出选择；B 输入槽单次等待从 10 ms 缩短至 1 ms，总等待上限仍为 500 ms，不增加线程。
- 记录应用接收至提交显示的耗时和提交间隔，区别于物理显示时间、触摸到像素延迟。静态画面间隔不可直接认定为卡顿。
- 分辨率、帧率、音乐、USB、触控配置不变。非 B 解码等待及 C 队列策略不变。

队列取帧由 VideoDecodeQueue 负责，参考链与解码器恢复仍归 VideoDecoder/VideoRecoveryPolicy；统计由 VideoPipelineStats 持有，按解码器生命周期清理且限制容量。
