# ADR-0008：导航与音乐共用焦点的可选策略

- 状态：Deprecated（2026-11-02 按用户要求定向回退混音调整，恢复独立导航焦点作音量对照）
- 日期：2026-11-02
- 作者：Codex
- 最后修改：2026-11-02，Codex

## 上下文

回退记录见 [导航混音定向回退](../AUDIO-MIX-ROLLBACK-20261102.md)。以下保留当时决策依据，不代表当前候选仍启用共享焦点；音量异常与本策略的因果尚未确认。

已核验H53原厂媒体流23、导航流11。现场LPCM导航因自定义流不受支持而无法创建AudioTrack，切换原厂配置后用户确认有声。独立导航焦点使用GAIN_TRANSIENT_MAY_DUCK，音乐在收到CAN_DUCK后降至软件音量0.2。用户要求默认保留已验证原厂路由，并可选择导航与音乐共同播放而不主动压低音乐。

## 决策

保留现有Android AudioManager/AudioTrack与同一AudioFocusCoordinator，不改PCM/Opus解码、USB或HUD。专用固定H53环境缺省使用原厂23／11，保留已保存选择。

增加持久化`navigation_ducking_enabled`，缺省false，在已启用原厂音频配置时提供设置入口。false仅将NAVIGATION轨焦点key映射为MEDIA23，与音乐共用同一listener/租约，输出轨仍为11；最后一轨退出才释放租约。true保留独立NAV11／MAY_DUCK。

外部LOSS、LOSS_TRANSIENT、CAN_DUCK和焦点拒绝继续生效，不将开关解释为忽略电话/系统提示。PHONE/ASSISTANT先启动时，新共享媒体请求静音并延迟，最后一条中断轨释放后只恢复明确deferred且仍有轨道的请求；外部拒绝不会自动重试。sink关闭先禁止新acquire和deferred恢复，随后按原流程释放轨道。

## 后果

正面：保留已验证导航输出，避免本应用导航申请造成自我降音，可随时开启旧模式对比；共享轨仍接受系统焦点控制。

负面：无音乐时导航也使用媒体焦点；电话反序及异步关闭需要明确deferred/closed状态。手机或车机HAL仍可能自行降音，本地测试不能证明扬声器始终保持原音乐音量。

## 替代方案

- 完全跳过导航焦点：无法借助同一租约可靠处理中断，未采用。
- 将导航改走媒体输出：改变已验证导航流和独立音量路径，未采用。
- 忽略所有降音/丢失回调：会影响电话与系统提示，未采用。
- 固定保留MAY_DUCK：不满足用户期望，保留为开关开启时的对照模式。

## 撤销条件

若原厂不接受共享焦点、导航出声回归或中断恢复不符合现场要求，先由用户选择开启降音恢复已验证模式；继续依据实际日志调整，不自动修改系统音量或绕过外部焦点拒绝。
