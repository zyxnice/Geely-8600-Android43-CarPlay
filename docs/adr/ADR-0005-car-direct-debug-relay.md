# ADR-0005：车机直接建立调试反向隧道

状态：Accepted（直连、主动断线、蜂窝数据恢复与本机SSH重启已实测；开机自动恢复未实现）

日期：2026-10-28

作者：Codex

最后修改：2026-10-28

## 上下文

iPhone同时承担CarPlay、热点及Termius反向转发。电脑SSH会话持续存在时，手机SSH反复关闭/重建，ADB采样多次中断。iOS挂起限制与现象相符，但尚未逐次证明原因。旧临时账号即将到期。车机API18限制可安装客户端版本。

## 决策

使用官方ConnectBot v1.9.13 OSS在车机建立仅转发的SSH连接：107回环15556映射车机本机5555。手机只做热点。使用独立密钥与专用nologin账号，服务端仅对该账号设置15秒探活、3次无回应清理；管理继续使用Cloud Assistant，SSH不运行服务器shell。

电脑使用固定服务器身份的数据转发监督脚本，在同一端点失败后重连。不改DiPlay、USB角色、原厂adbd和开机脚本，不把工具装进CarPlay主进程。

## 后果

正面：用户停止Termius、车机切回DiPlay后仍可执行ADB；服务端主动断线与蜂窝数据恢复后车机均已自动重新认证，本机SSH被终止后监督脚本也已重新建立隧道。调试不再要求iPhone保持Termius前台。

负面：增加一个车机调试应用与专用服务器账号；移动网络仍是依赖。旧版ConnectBot的转发失败处理和重试存在源码风险，开机不能自动恢复，重启后需点保存主机。OpenSSH7.4只能将reverse监听限制到回环接口，不能按key限制单一端口。

## 替代方案

- 继续手机Termius并添加保活：无法解除iOS挂起依赖，不作为主方案。
- 将SSH实现嵌入DiPlay：扩大播放应用的网络、认证及生命周期职责，暂不采用。
- 直接暴露ADB公网端口：扩大设备访问面，不采用。
- 立即自研SSH客户端或修改车机启动服务：维护与系统侵入成本高，先实测独立成熟客户端；若连续断网恢复失败再选择最小必要补丁。

## 撤销条件

若客户端影响CarPlay资源、不能满足所需的断线恢复，或不再需要远程调试，则断开/卸载独立应用、撤销专用密钥与账号、停止本机监督进程。撤销服务端Match时核对后续配置变更，保留其他账号与业务服务。
