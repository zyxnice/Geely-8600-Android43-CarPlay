# CarPlay 本机交互与积压模拟

## 用途与边界

减少每次修改都要求用户上车、插线、滑动的次数。当前提供无界面的本机模拟，复用生产源码，在安装 APK 前自动检查协议交互与可控的积压/恢复场景；不把 Windows 的执行速度当作车机帧率。

本轮仅增加 `src/test` 和本机脚本，不改变生产 App、USB、认证或车机配置，也不安装 APK。

| 层次 | 实际执行 | 明确未覆盖 |
| --- | --- | --- |
| 手机协议对端 | 真实回环 TCP/UDP；加密 RTSP SETUP/RECORD/TEARDOWN；生产 AirPlaySession、CarPlayMediaEngine、ScreenStream、AudioStream、HID 编码 | iPhone 系统、iAP2/MFi/Pair-Verify 握手和 USB/NCM 驱动 |
| 媒体传输 | 加密视频消息、拆分写入、连续 nonce、认证失败、视频重连、音频 RTP、关键帧请求与返回 | 合成 NAL 仅验证字节交付，不是可播放 H264；PCM 仅验证交付，不经过 AudioTrack |
| 积压压力 | 真实 VideoDecodeQueue、VideoReferenceChain、VideoRecoveryPolicy、VideoOutputBatch；虚拟时钟重复注入故障 | 调度循环和解码耗时是测试模型，不是 AndroidMediaSink 或 Freescale MediaCodec；没有物理屏幕 FPS |

协议测试使用 Robolectric API29 shadow 和 Java 加密实现；不是 API18 原生 JNI 兼容验证。测试代码按仓库既有 `CarPlayScreenReplacementTest` 的方式预置配对后的测试共享密钥；控制通道密钥为固定测试夹具，通过反射注入测试实例，生产 APK 不包含该入口。所有密钥均为合成测试值，不读取真实认证资产。

## 一条命令运行

在仓库根目录使用 PowerShell 7：

```powershell
.\scripts\run-carplay-simulation.ps1 -Repeats 3
```

使用仓库现有 JDK25 / Gradle / Android SDK 与测试依赖，不需要 ADB、车机、手机热点或服务器。默认查找本工作区已有 JDK，其他机器可传 `-JavaHome`；首次缺少构建依赖时 Gradle 可能联网下载，不保证首次离线可运行。

脚本自动创建新的 `build/reports/carplay-local-时间戳` 目录；也可用 `-OutputDirectory` 指定一个尚不存在的目录。每轮保存 Gradle 日志、两个 JUnit XML 和 `virtual-pressure.csv`；整体保存源码 SHA256、Git 状态和 `summary.json`。失败立即退出并保留失败日志，不生成成功汇总。重复运行不覆盖以前的结果。

## 场景与读数

- 稳定 30 / 60 帧输入：用于验证正常路径没有凭空恢复或丢帧。
- 120ms 一批的突发到达：区分源头/链路间歇与解码积压。
- 每 500ms 暂停工作线程 27ms：模拟调度暂停的影响；不是重放真实 Dalvik GC。
- 单次暂停 400ms：触发超过 250ms 的过期帧路径。
- 同样暂停，但手机延迟 1500ms 才响应关键帧：检查恢复空窗是否随发送端等待扩大。
- 每帧解码服务耗时 45ms：模拟持续处理能力不足。
- 45ms 解码叠加 400ms 工作线程暂停：检查多个已解码输出同时可取时的最新帧选择与旧帧释放。
- 静态画面 1500ms 后恢复：长输出间隔不能单独算作积压。

`sourceFrames/rendered/superseded/recoveries` 是合成场景计数；`queuePeakFrames/Bytes` 是模型中实际队列最大占用；`maxQueueAgeMs`、`maxReceiveToSubmitMs`、`maxOutputGapMs` 使用虚拟毫秒。模型默认合成帧为 4096 字节，解码服务耗时 10ms、4 个在途槽位；这些是显式假设，不是车机测量值。CSV 供机器对比，不是车机性能报表。

## 后续优化使用方式

1. 每次改动先运行协议与压力矩阵，确认没有破坏触控、重连、音频独立性和引用帧恢复。
2. 新增故障场景应给出输入速率、突发节奏、暂停/解码耗时与关键帧响应延迟，不通过降低断言要求制造通过。
3. 在同一组输入与假设下比较修改前后结果；不使用不同假设的数字宣称性能提升。
4. 只把通过本机检查且有明确收益假设的候选送上车，最后核对硬件解码、USB 冷启动、画面连续性与音乐/跟手主观反馈。

当前没有实车逐帧原始轨迹，只有先前 5 秒聚合日志和少量 GC 等待记录，因此本矩阵是故障注入，不宣称精确重现当前车机全部卡顿。
