# ADR-0012：内核 NCM 连接准备阶段受限启用当前 iPhone 网卡

- 状态：Accepted（本候选实现已采用，尚未实车验收）
- 日期：2026-11-08
- 作者：Codex，依据用户要求在 APP 内加入网卡启动逻辑
- 最后修改：2026-11-08

## 上下文

另一会话的本地记录 `output/usb-takeover-20261108/HOST-CDP-NCM-DOWN.md` 显示：
Host＋CDP、Apple配置6和 `cdc_ncm` 均成立时，对应网卡 `usb1` 仍为 DOWN，且没有 IPv6。
该会话手工 UP 后出现 link-local IPv6 并进入 CarPlay，用户确认连接成功但仍有卡顿。
这证明该次 DOWN 是连接缺失条件，不证明所有断连都由 DOWN 导致，也不证明整体流畅度。
用户要求 APP 在原有运行时 Host＋CDP 准备之外启动网卡，已满足状态就不重复操作，保留系统默认及 ADB 配置。

主 checkout 仍是用户态 NCM。内核路径已有只读 sysfs 发现、完整枚举绑定及作用域 IPv6 等待，
却要求人工准备 DOWN 网卡。本次从既有内核候选创建隔离副本，不修改另一会话源码，不把内核架构移植到主 checkout。
既有 ADR-0001/0003 的原厂桥与短生命周期 helper 协议继续复用；本决定增加内核网卡 UP 这一明确副作用。

用户随后要求合到画面流畅里程碑分支。本记录连同实现整合到 `milestone/usb-smooth-userspace-ncm-20261108`，
保留其 `GEELY_KERNEL_NCM=false` 和已有内核/用户态双分支，不切换已实测的用户态传输。
该分支开启运行时Host＋CDP准备，内核UP实现随源码保留但默认不执行；原实车安装包记录不变，新构建仍待验收。

## 决策

网卡事实和绑定身份仍由 `GeelyKernelNcmLink` 拥有，在 `awaitAddress` 前置步骤检查 IFF_UP。
已 UP 不调用启用 helper；DOWN 每个绑定最多尝试一次。传递完整 USB 身份、实际网卡名、ifindex、MAC、控制/数据接口及 alternate，
不写死网卡名或将名字当作物理 USB 口标识。`GeelyKernelNcmPreparation` 只负责异步单飞请求、租约与取消。

API18 helper 在固定 H53/root/当前boot/Host且供电健康、固定电话控制器、Apple配置6、cdc_ncm 驱动及完整身份全部回读匹配后，
仅执行固定 `/system/bin/busybox ifconfig <当前网卡> up`。启用前重新确认 DOWN，启用后确认同一身份和 UP；
再由原绑定等待非暂定、正确 ifindex 的 link-local IPv6，继续原 CarPlay 流程。helper 源码纳入现有 API18 单独编译与 DEX 打包。
正常准备目标为CDP；已配置6的活跃SDP按既有策略保留，网卡UP允许SDP/CDP两种通信协议，不改活跃链路的充电模式。

网卡UP仅 opt-in 内核分支及固定 API18/C3ALFUS/06.03.08600.H53.00060 适用，专用变体开启原有运行时准备 metadata。
Host＋CDP 策略已就绪时不重复操作，不保留旧空发现电源循环；本轮不修改系统持久配置、启动默认、ADB设置、IP、IPv6开关、路由或DNS。
失败和关闭不 DOWN，不接管其他网卡或新增其他设备的通用命令接口，不增加新的特权获取通道。

请求租约6秒、调用端最多等待7秒、helper看门狗8秒。取消删除私有租约；未返回的Binder任务保持单飞。
已发出的单次 ioctl 不能撤回；最终校验到按名称操作之间非原子，不能宣称消除了设备替换竞态。

## 后果

正面：将已证实缺失的行政 UP 步骤纳入原连接 owner，保留已 UP 状态，具备匹配前后状态的日志与可测试策略；
无需每次人工命令，不改变系统默认，主 checkout 和其他会话候选隔离。

负面：依赖固定固件原厂 root 桥和 busybox。受限操作仍是系统网卡状态变化，取消及替换存在上述有限窗口；
UP 不能保证 IPv6、手机授权或最终 CarPlay 成功。未返回的Binder会阻止后续启用，需记录并结束该故障会话。
本地测试及APK构建不能替代实车冷启动、拔插、进入视频和长期稳定性验证。

## 替代方案

- 保持人工 UP：现场已经有效，但不满足用户要求 APP 自动处理。
- 系统开机脚本、init 或 persist：超出应用运行时范围，不采用。
- 在发现阶段周期性 `ifconfig usb1 up`：名称不是身份，会产生重复调用并可能误操作替换后的接口，不采用。
- 同时设置 IPv6、IP 或默认路由：没有此类必要性的现场证据，扩大网络副作用，不采用。
- 失败时 DOWN 回滚：可能破坏已被其他连接使用的网卡，不采用。
- 把整套内核 NCM 移入当前主仓：会覆盖其他会话工作和用户态路径，当前仅在隔离内核候选实现。

## 撤销条件

平台、固件、boot 或完整枚举身份不匹配立即拒绝。若 OEM 桥无法完成受限调用、身份回读不可靠、
或实车出现与新增 UP 相关的网络影响，关闭该候选启用逻辑并回退已验收包，保留证据再定位；不通过扩大权限兜底。
若系统原生管理已稳定将该网卡 UP，本流程自然只读；有受支持的系统接口时再评估替换原厂桥。
