# ADR-0002：8600 导航观测与受控原厂 HUD 试验

状态：Accepted（观测／原厂接收出口继续有效；来源控制由ADR-0010补充替代，旧直接输出策略为历史）

日期：2026-10-26

作者：Codex

最后修改：2026-11-03

## 上下文

8600 原厂接收高德结构化导航广播，按车型转换后调用车辆侧透传服务。初始 DiPlay 可订阅和解析 iAP2 导航，但车辆输出面向 BYD。原厂 10019 会触发导航模式和条件性能量管理逻辑，10001 也更新服务区、摄像头、收费站和隧道；接收端共用导航状态。11月1日已取得目标手机路线元数据及trial2本次现场可用反馈，可靠来源互斥或进程死亡后接收端清除仍无完整实车证据。

## 决策

2026-11-03更新：行驶隔离已确认原车高德与CarPlay竞争。新增[ADR-0010](ADR-0010-hud-exclusive-navigation.md)管理原车高德的临时禁用与恢复；独占候选默认开启，已交付但未装车。导航广播出口仍沿用本文的固定接收端约束，特权助手仅控制应用启用状态，不写HUD车辆数据。下文的忽略原车状态、内容去重和距离5秒清除均是各自日期的历史阶段，现行行为以[HUD说明](../GEELY-8600-HUD.md)为准。

2026-11-02 后续回退：用户反馈内容去重无效，明确要求撤销该变更。仅恢复此前整帧比较（包含距离更新时间），保留默认开启、手动OFF、忽略原车状态及其它守卫。下方“按实际字段变化发送”已被本项取代；该负面反馈不单独证明闪烁根因。回退范围和装车结果见对应工作记录。

2026-11-02 当前决策（覆盖下方历史来源保护与人工确认策略）：按用户明确要求，CarPlay作为唯一导航来源，默认开启并保存手动OFF；删除原车状态监听、分类器和确认入口。接收器身份、租约、代次、新鲜度及失败清除策略保留。比较实际发送字段抑制相同内容，忽略接收时间差异；新数据继续刷新5秒有效期。

正面：避免原车状态UNKNOWN阻止CarPlay HUD，并减少相同导航字段重复写入。负面：不再避让其他来源，尚在后台运行的原车高德可能覆盖共享状态；去重后的物理持续显示能力及闪烁效果待验。本次不卸载原车高德、不引入MCU/CAN写入。

替代方案：保留UNKNOWN和人工确认会违反当前明确使用要求，不采用；固定频率重发会违反仅变化发送要求，不采用。撤销条件：正常CarPlay或HUD显示受影响时关闭HUD或回退已核验APK，进一步核实物理显示刷新契约后再调整。

以下2026-11-01及之前段落为历史决策，涉及来源检测、UNKNOWN等待及手动确认的行为已由上述决策替代。


2026-11-01后续：用户明确要求HUD默认开启。默认偏好改ON并保存手动OFF；运行租约仍可被接管/错误撤销。为保留来源保护，UNKNOWN不再依靠默认偏好放行，等待明确空闲事件或当次人工停车确认。清除失败状态不会因关闭而抹掉，迟到等待状态不能覆盖手动OFF。此变更不代表异常恢复已完成实车验收。

最初观测基线为 fork main 5ab0777；当前受控出口已随功能提交1fbc7cc合入main。局部提取厂商无关的iAP2导航解析，保留BYD对外契约，仅固定API18/C3ALFUS/H53.00060及geelyUsb opt-in生效。默认只观测；当次人工停车确认后，以显式广播交给身份核验通过的原厂AutoNaviReceiver。导航证据、通道代次、租约和新鲜度守卫控制发送与清除，不直接调用MCU/CAN或USB特权桥写HUD。接受的是人工独占试验方案，不是默认自动运行或已完成全场景验收。

## 后果

2026-11-01修订：实车原高德由语音绑定及AutoBackgroundService常驻，用户未主动开启原导航；进程存在不足以证明正在引导。移除进程拒绝，改由10019的8/10与9/12及10001路线证据识别导航占用。已知ACTIVE只由明确结束释放，不以TTL清空；无历史状态时保留UNKNOWN，仅通过本次停车人工确认原导航未启动后试验。仍无跨进程原子互斥，10001判据不是完整协议声明。

2026-10-31续作：用户要求实现原方案。保留只观测为默认模式，新增固定平台/包/原厂APK及ODEX身份守卫的显式广播试验出口。一次应用运行需人工确认启用，不恢复持久授权；进程内租约保证单一写者，失效/暂停/关闭时仅对仍由本次试验拥有的输出尝试结束，已知其他来源接管后不补结束。事件/发送各处检查控制通道代次，Binder已发出不可撤回。UI显示实际开关与拒绝/清除失败原因。仍不调用原始透传或特权桥。

该续作只接受“停车/台架、人工独占、默认关闭”的试验范围，没有把接收端TTL、来源原子互斥或强杀后的清除写成已解决。原先安装后关机要求已被用户取消；11月1日用户反馈候选“可以了”，随后授权提交合入，仍不构成持续无人值守操作授权。

正面：能先验证实际手机数据，复用同一协议解析，避免把广播可达当作安全性或显示验收；现有普通构建不自动进入吉利观测。

负面：开始/结束共享原厂导航状态，来源监控非原子，历史状态可能未知；强杀后可能残留显示。本次可用反馈不能证明全部车型图标、来源切换和异常恢复已通过，仍需专项验证。

## 替代方案

- 直接复用 BYD 广播：目标包、ICON 字段和厂商映射不一致，不采用。
- 默认自动发送10001/10019：副作用、来源竞争和异常清除尚无闭环，不采用；当前仅接受人工确认后的受控试验出口。
- 直接 MCU/CAN 或复用 USB 特权助手：超出当前已核验接口与授权范围，不采用。
- 另写 iAP2 解析：增加双重协议 owner，无必要。

## 撤销条件

观测或试验影响正常CarPlay时关闭试验或回退已核验APK；关闭应用不保证物理HUD残留自动清除，应检查并恢复原车导航。未来核实更窄的原厂出口、来源互斥和失活清除后再修订输出决策。BYD wrapper保留为既有厂商边界，仅在独立厂商迁移需求中考虑退役。

## 基线同步

本次能力与限制以 docs/GEELY-8600-HUD.md 为准；既有 USB ADR 和 P21/P22 历史状态不被本次观测验收覆盖。
