# ADR-0002：8600 导航观测与受控原厂 HUD 试验

状态：Proposed（观测及手动试验实现；车侧显示与恢复尚未验收）

日期：2026-10-26

作者：Codex

最后修改：2026-11-01

## 上下文

8600 原厂接收高德结构化导航广播，按车型转换后调用车辆侧透传服务。已有 DiPlay 可订阅和解析 iAP2 导航，但实际车辆输出面向 BYD。原厂 10019 会触发导航模式和条件性能量管理逻辑，10001 也更新服务区、摄像头、收费站和隧道；接收端共用导航状态。尚无目标手机高德完整元数据、可靠来源互斥或进程死亡后接收端清除的实车证据。

## 决策

开发基线为 fork main 5ab0777。局部提取厂商无关的 iAP2 导航解析，保留 BYD 对外适配语义。仅在显式启用 metadata 且匹配 API18/C3ALFUS/8600 的测试变体内开启导航观测，按控制通道代次拒绝旧回调、核对字段完整性、限量输出诊断。吉利映射仅生成离线候选数据，不创建/发送原厂广播，不调用车辆透传或 USB 特权桥写车辆数据。车侧出口、所有权交接和清除机制在证据齐备后另行修订本 ADR。

## 后果

2026-11-01修订：实车原高德由语音绑定及AutoBackgroundService常驻，用户未主动开启原导航；进程存在不足以证明正在引导。移除进程拒绝，改由10019的8/10与9/12及10001路线证据识别导航占用。已知ACTIVE只由明确结束释放，不以TTL清空；无历史状态时保留UNKNOWN，仅通过本次停车人工确认原导航未启动后试验。仍无跨进程原子互斥，10001判据不是完整协议声明。

2026-10-31续作：用户要求实现原方案。保留只观测为默认模式，新增固定平台/包/原厂APK及ODEX身份守卫的显式广播试验出口。一次应用运行需人工确认启用，不恢复持久授权；进程内租约保证单一写者，失效/暂停/关闭时仅对仍由本次试验拥有的输出尝试结束，已知其他来源接管后不补结束。事件/发送各处检查控制通道代次，Binder已发出不可撤回。UI显示实际开关与拒绝/清除失败原因。仍不调用原始透传或特权桥。

该续作只接受“停车/台架、人工独占、默认关闭”的试验范围，没有把接收端TTL、来源原子互斥或强杀后的清除写成已解决。用户另行授权安装后关机，不等同于授权后台进行HUD输出试验。

正面：能先验证实际手机数据，复用同一协议解析，避免把广播可达当作安全性或显示验收；现有普通构建不自动进入吉利观测。

负面：本版本不能在 HUD 显示 CarPlay 导航；离线映射不能证明车型图标或车辆状态正确，仍需后续现场验证。

## 替代方案

- 直接复用 BYD 广播：目标包、ICON 字段和厂商映射不一致，不采用。
- 立即发送 10001/10019：副作用、来源竞争和异常清除尚无闭环，不采用。
- 直接 MCU/CAN 或复用 USB 特权助手：超出当前已核验接口与授权范围，不采用。
- 另写 iAP2 解析：增加双重协议 owner，无必要。

## 撤销条件

观测影响正常 CarPlay 时关闭 metadata 或回退测试 APK。未来核实更窄的原厂出口、来源互斥和失活清除后，修订输出决策。BYD wrapper 保留为既有厂商边界，仅在独立厂商迁移需求中考虑退役。

## 基线同步

本次能力与限制以 docs/GEELY-8600-HUD.md 为准；既有 USB ADR 和 P21/P22 历史状态不被本次观测验收覆盖。
