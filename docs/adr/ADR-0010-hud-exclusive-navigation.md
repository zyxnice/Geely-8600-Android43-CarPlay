# ADR-0010：DiPlay 管理原车高德的 HUD 独占

- 状态：Accepted
- 日期：2026-11-03
- 作者：Codex（用户授权）
- 最后修改：2026-11-03

## 上下文

原车高德和 DiPlay 向同一原厂接收端发送导航数据。2026-11-03 行驶隔离中，禁用原车高德后零距离覆盖消失，用户确认上下两处均不闪。用户要求由 DiPlay 控制隔离，制作新包但不装车。基线为 audio-mix-rollback（SHA-256 前缀 9d2283914adc），保留媒体23／导航11。

## 决策

仅 API18、C3ALFUS、06.03.08600.H53.00060 专用包支持独占，独占偏好默认开启；HUD 总开关原有选择继续保留。有效路线且持有现有 HUD owner 时，异步准备独占，确认原车高德已禁用／原本禁用／不存在后才允许发送导航。

独占控制归 GeelyHudExclusiveControl；固定 root 助手只操作 com.autonavi.amapauto 的 user 0 启用状态，沿用 GeelyUsbOemBridge 的 H53 通道，不开放任意命令或车辆透传。发送器仍使用原厂广播接收端。

助手持有文件锁并在修改前 fsync 保存原始0/1状态及 uid、首次安装和更新时间。导航 worker 每秒续租，租约12秒；独立助手每秒核验并在租约失效后恢复。恢复仅针对同一安装实例且当前仍为自己写入的3状态。原本禁用、用户卸载或替换的应用不启用、不安装。失败保留恢复记录；不把 OEM Binder 返回当作修改成功。

导航结束先请求清屏再释放独占。手动恢复／关闭独占同时关闭 HUD 总开关，由导航 worker 清屏后释放，避免再次接管。BootReceiver 在开机启动偏好判断前启动固定恢复服务；DiPlayActivity 启动时也检查恢复记录。开机广播未送达或应用被系统强行停止时，只能在下次 DiPlay 获得运行机会恢复，不能承诺断电期间或任意系统故障下自动恢复。

## 后果

- 正面：无须修改原厂 APK，保留已卸载／已禁用状态；进程崩溃时有独立租约恢复；原始启用值可恢复。
- 负面：独占期间原车高德及其语音导航不可用；启动独占有短暂等待；root 桥及 PackageManager 故障可能延迟恢复。文件 fsync 不等同于任意存储故障的绝对保障；恢复失败会显示错误并保留记录。
- 本次仅本地测试、构建和包体校验；断开、崩溃、重启及原车语音恢复需实车验证。当前用户已卸载高德，不能用该场景替代安装状态下的隔离验收。

## 替代方案

- 修改高德发送端：用户要求控制在 DiPlay 内，且有签名／兼容成本，未选。
- 修改原厂接收服务做来源选择：影响范围更大，未选。
- 每帧抢写或过滤所有0：不消除来源竞争，并会损伤合法到达／结束语义，未选。
- 单次 force-stop：已被绑定服务立即拉起，未选。

## 撤销条件

独占影响原车关键功能、恢复无法可靠验证，或出现可验证的原厂 HUD 输出控制接口时停用本方案。回退 APK 前先使用恢复按钮并核实原车启用状态；旧包不具备读取新恢复记录的能力。
